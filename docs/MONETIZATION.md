# Monetization Strategy

## Product Opinion

The app should not charge for basic daily tracking. That would make early adoption harder and reduce feedback.

The best paid angle is professional planning value: saving time, avoiding missed steps, and producing outputs that are useful on a job.

## Free Tier

- Recurring daily tasks.
- One-time tasks.
- Basic weekly recap.
- One active project or a small number of active projects.
- Dark mode and language selection.

## Pro Tier Candidates

- Unlimited active projects.
- Project templates.
- Export project plan to PDF/CSV.
- Monthly project progress reports.
- Photo attachments.
- Advanced reminders.
- Archive/search completed projects.
- Backup/import/export.

## Pricing Hypotheses

These are hypotheses, not decisions:

- One-time Pro unlock: simple and friendly for personal users.
- Monthly subscription: better if professional workflows, sync, templates, and reports become strong enough.
- Annual plan: useful later if the target becomes tradespeople or site managers.

## Constructive Caution

Do not monetize before retention is proven. If people stop using the app after two days, paid features will not fix the core problem.

Before adding payments, validate:

- Do users create recurring tasks?
- Do users create projects with more than five steps?
- Do users return after one week?
- Do users ask for export, templates, or reports?
- Would a site manager show this to another site manager?
